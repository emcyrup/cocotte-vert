# 公式LINE からの予約登録

スタッフが公式LINE へ「予約登録 …」と送ると、Bot が読み取った内容を復唱し、
［登録］が押されたときだけ予約カレンダーに入る。

```
スタッフ（LINE）                       システム
「予約登録 8/20 14時 田中花子 カット」 →  Haiku で解釈 → 下書きを保存
                                      ←  内容を復唱し［登録］［やめる］
［登録］                              →  reservations に登録 → Slack へ新規予約通知
                                      ←  「予約を登録しました」
```

**その場では予約を作らない。** 文章は AI が読み取っているため、読み違えたまま入れると
お客様の予定として残ってしまう。必ず内容を見せて確かめてもらう（シフト変更の確定と同じ考え方）。

## 使える場所

2か所。どちらでも同じように使える。

| 場所 | 誰が使えるか |
|---|---|
| スタッフ用の LINE グループ | そのグループの発言（スタッフ通知先に設定済みのグループのみ） |
| Bot との 1:1 のトーク | **連携済みスタッフ**の発言のみ |

顧客の発言を予約として読み取らないよう、**接頭辞を必須**にしている。
`予約登録` / `予約追加` / `予約入力` / `新規予約` のいずれかで始まる発言だけが対象。

一覧の問い合わせ（[予約確認](staff-manual.md#スタッフ用のlineグループから予約を確認する)）と
紛れないよう、登録の判定を先に行う。「予約登録 明日14時 …」が「明日の予約」の問い合わせとして
読まれることはない。

## 書き方

お名前・日付・時刻が読み取れれば、文章の形は自由。

| 送る文の例 | 解釈される内容 |
|---|---|
| `予約登録 8/20 14時 田中花子 カット 担当佐藤` | 8/20 14:00 田中花子様／カット／佐藤 |
| `予約登録 明日10:00 山田 090-1234-5678 シャンプー` | 翌日 10:00 山田様／シャンプー |
| `予約登録 8/27 9時 山本さくら お泊まり 2時間` | 8/27 09:00／所要120分 |

- **時刻の午前・午後が分からない場合は読み取らない**（「2時」だけなど）
- コース・担当・所要時間は任意。書かれていなければ「未定」で登録し、あとから画面で直せる
- 所要時間を書かなければ、コースに設定された所要時間に従う
- 担当は在職スタッフの名前と突き合わせる。**同名が複数いるときは担当未定**にする
  （別人を担当にすると予定が食い違うため）

読み取れないときは予約を作らず、書き方を案内して終わる。

## お客様の特定

1. **電話番号**が書かれていて一致すれば、その方（電話番号はこのシステムの突合キー）
2. なければ**お名前で完全一致**（姓名の間の空白は無視して比べる）
3. それも無ければ**部分一致**（「田中」で「田中花子」を引き当てる）

結果によって返すものが変わる。

| 結果 | Bot の返し方 |
|---|---|
| 1人に絞れた | そのまま内容の確認へ |
| 複数いる | 候補を並べて選ばせる（電話番号は**下4桁だけ**添える）。「新しいお客様として登録」も選べる |
| 誰もいない | 新しいお客様として登録する前提で内容の確認へ |

**同名が複数いるときに勝手に決めない。** 別のお客様の予定に入れてしまうと、
リマインドも誤った相手へ飛ぶため。

新しいお客様は**お名前だけでも登録できる**。ただし電話番号が無いとリマインド配信の突合が
できないため、登録後の返信で「店舗管理画面から追加してください」と促す。
書かれた電話番号が既存のお客様と重なる場合は、新しく作らずその方に寄せる。

## 下書き（reservation_drafts）

読み取った内容は `reservation_drafts` に置く。予約そのものは
`reservationService.createManual` を通して作る（予約の書き込みは必ずあのアダプタを経由する）。

| 状態 | 意味 |
|---|---|
| `pending` | 内容を返して、［登録］の返事を待っている |
| `registered` | 登録済み。`reservation_id` に予約番号が入る |
| `cancelled` | ［やめる］が押された |

守っていること。

- **送られてきた場所でしか動かせない。** 下書きの取得・更新はすべて `source_type` /
  `source_id` を条件に入れている。別のトークからボタンを押されても他人の下書きは動かない
- **二重に押されても2件入らない。** 先に下書きを `registered` へ倒し、取れたときだけ予約を作る。
  予約の作成に失敗したら `pending` へ戻すので、押し直せる
- **24時間で期限切れ。** 何日も前のボタンを押されて、意図しない予約が入るのを防ぐ
- **登録できなかったことは必ず伝える。** 黙って終わると、入っていない予約を入ったつもりで
  運用してしまう。本人へ返信し、Slack へも出す

## 登録したあと

- 予約カレンダーと予約一覧に `confirmed`（確定）で出る
- Slack へ「新規予約」が飛ぶ（既存の手入力予約と同じ通知）
- 2日前になれば前々日確認の対象になり、来店登録すれば7日後フォローの対象にもなる

取り消し・日時の変更は管理画面から行う。LINE からはできない。
