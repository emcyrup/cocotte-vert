# SNS キャプションの自動生成

管理画面の「SNS投稿」で **「✨ 自動で書く」** を押すと、その投稿の写真を Claude に見せて
キャプションの下書きを作る。Instagram とスレッズで別々に生成できる。

**作るのは下書きだけ。** 投稿は従来どおりスタッフが内容を確かめてから押す。
生成そのものは SNS へ何も送らないので、`IG_POST_MODE` / `THREADS_POST_MODE` とは無関係に動く。

## 設定

| 環境変数 | 既定 | 説明 |
|---|---|---|
| `ANTHROPIC_API_KEY` | （必須） | 未設定だとボタンを押しても 503。投稿機能そのものは動く |
| `CAPTION_MODEL` | `claude-opus-5` | 写真を見て文章を書くモデル |
| `STORE_NAME` | `ここっとベール` | 店名。プロンプトに入り、ハッシュタグにも使われる |

`CAPTION_MODEL` を `claude-haiku-4-5` にすると費用は10分の1以下になるが、文章はやや素っ気なくなる。
まず既定で試して、費用が気になってから下げるのがよい。

## 何を送っているか

- **写真だけ**。顧客名・わんちゃんの名前・電話番号・カルテの内容は一切送っていない。
- 写真は多くても**4枚**。20枚選んでいても等間隔で間引く（全部送っても文章はほとんど変わらず、
  画像1枚あたりのトークンが大きいため費用だけが増える）。
- スタッフが「ひとこと補足」に入れた文（任意・200文字まで）。

写真そのものはこのあと SNS で公開するものなので、外部モデルに見せる範囲は投稿と同じ。
ただし**投稿しない写真を選択に混ぜたまま生成すると、その写真も送られる**点には注意。

## 書かせ方

プロンプトで次を指示している（`src/ai/writeCaption.js`）。

- 写真から分かることだけを書く。**犬種・名前・年齢・飼い主様のことは推測させない**
- 料金・キャンペーン・予約の空き状況など、確認できない情報を書かせない
- 写真に人が写っていても、その人については書かせない
- 絵文字は2〜3個まで。ハッシュタグは店名と地域名を1つずつ含める

本文とハッシュタグは構造化出力で別々に受け取り、サーバ側で1本の文字列に組み立てる。
文字数の上限（Instagram 2200 / スレッズ 500）はスキーマでは表現できないため、
**本文より先にハッシュタグを落として**収める（本文が途中で切れるほうが読み手には不自然なため）。

## 失敗したとき

画面にトーストで理由が出る。サーバのログには `[caption]` で出る。

| 表示 | 意味 | 対処 |
|---|---|---|
| 自動生成が設定されていません | `ANTHROPIC_API_KEY` が未設定 | `.env` に設定して再起動 |
| 写真の内容から文章を作れませんでした | 安全側の判定で断られた | 別の写真で試す |
| 文章の作成に失敗しました | API エラー（キー誤り・混雑など） | しばらく待つ。続くならキーを確認 |
| うまく書けませんでした | 応答が想定の形式でなかった | もう一度押す |

## 動作確認

API キーがなくても、ここまでは確かめられる。

```bash
# 写真を1枚上げる
F=$(curl -s -u admin:pass -X POST --data-binary @photo.jpg \
      -H 'Content-Type: image/jpeg' http://localhost:3000/api/admin/sns/photos \
      | python3 -c 'import sys,json;print(json.load(sys.stdin)["file"])')

# 下書きを作る
curl -s -u admin:pass -X POST -H 'Content-Type: application/json' \
  -d "{\"files\":[\"$F\"],\"platform\":\"instagram\",\"hint\":\"今日は保育コース\"}" \
  http://localhost:3000/api/admin/sns/caption
```

キー未設定なら `{"error":"no_api_key"}`（503）、キーが誤っていれば `{"error":"api_error"}`（502）が返る。
