# SNS 投稿先の追加と設定

管理画面「SNS投稿」は、**投稿先ごとに本文・写真の範囲・タイミングを別々に決めて**送る。
チェックを入れた投稿先の数だけ別々の投稿として登録され、それぞれのタイミングで公開される。

対応している投稿先と決まりごとは `src/sns/platforms.js` の1か所にまとまっている。

| 投稿先 | 1投稿の写真 | 超過分 | 本文の上限 | 写真必須 |
|---|---|---|---|---|
| Instagram | 10枚 | **2投稿目へ分割**（「つづき（2/2）」を自動追記） | 2200 | ○ |
| スレッズ | 20枚 | 打ち切り | 500 | ○ |
| X | 4枚 | 打ち切り | 280 | — |
| WordPress | 20枚 | 打ち切り | 20000 | — |

分割しない投稿先で打ち切るのは、連投になって読み手の印象が悪くなるため。

**「写真必須」が — の投稿先は、写真なし・本文だけで投稿できる。** 下書きの自動生成も、
写真の代わりに**スタッフが書いた要点**から書ける（[写真なしの投稿](#写真なしの投稿wordpress--x)）。
この列は `photoRequired` そのもので、投稿 API・配信・画面の3か所が同じ値を見る。
**表に書いて実際は見ていない、という状態を作らないこと。** 一度そうなっていて、
WordPress は `photoRequired: false` なのに写真ゼロが弾かれていた。

## いま使える状態か

画面は起動時に `GET /api/admin/sns/platforms` を読み、投稿先ごとに次を出す。

- **実投稿** … `*_POST_MODE=live`。押すと本当に投稿される
- **dry_run** … 設定はあるが投稿しない（既定）
- **未設定** … 認証情報がない。チェックできない

未設定の投稿先も一覧から消さずに「未設定」と出す。黙って消えると設定漏れに気付けないため。

## X（旧Twitter）を使うには

> ⚠️ **X の書き込み API は有料。** 2023年以降、投稿できるのは Basic 以上の有料プラン
> （月100ドル前後）。無料枠は投稿数がごく少なく、日々の運用には足りない。
> 契約前でも画面には「未設定」として出る。

1. [developer.x.com](https://developer.x.com/) でアプリを作る
2. アプリの権限を **Read and write** にする（既定は読み取りのみ。ここを変えずにトークンを
   発行すると、投稿だけが 403 で失敗する。**権限を変えたらトークンを再発行する**）
3. 次の4つを発行して `.env` に入れる

```
X_API_KEY=          # Consumer Keys の API Key
X_API_SECRET=       # 同 API Key Secret
X_ACCESS_TOKEN=     # Access Token（アプリの所有アカウントとして投稿する）
X_ACCESS_SECRET=    # Access Token Secret
X_POST_MODE=dry_run # 確認できたら live
```

## WordPress を使うには

WordPress の REST API を使う。追加のプラグインは要らない（WordPress 4.7 以降は標準搭載）。

1. WordPress 管理画面 → **ユーザー → プロフィール → アプリケーションパスワード**
2. 名前を付けて「新しいアプリケーションパスワードを追加」。表示される
   `xxxx xxxx xxxx xxxx xxxx xxxx` を控える（**この1回しか表示されない**）
3. `.env` に入れる

```
WP_BASE_URL=https://example.com   # サイトのURL（/wp-json は付けない）
WP_USER=                          # ログイン名（メールアドレスではない）
WP_APP_PASSWORD=                  # 上で発行したもの。空白は入れたままでよい
WP_STATUS=draft                   # draft=下書きで止める（既定） / publish=そのまま公開
WP_POST_MODE=dry_run              # 確認できたら live
```

> **通常のログインパスワードは使わない。** アプリケーションパスワードは投稿だけに使える
> 別のパスワードで、いつでも個別に取り消せる。
>
> **まずは `WP_STATUS=draft` で試すこと。** 下書きに入るので、WordPress 側で中身を確かめてから
> 公開できる。慣れてから `publish` に変える。

### 記事の作られ方

SNS のキャプションは本文だけだが、記事にはタイトルが要る。**1行目をタイトル、残りを本文**にする。

```
今日のトリミング          ← タイトル
                          （空行）
マロンちゃんが来てくれました。  ← 本文
さっぱりしました。
```

1行しかなければ、それをタイトルにも本文にも使う（タイトルだけの記事は一覧で中身が分からないため）。
1行目が60文字を超えるときはタイトルを切り、本文には全文を残す。

### 写真の扱い

**写真は WordPress のメディアライブラリへ入れてから記事に載せる。** こちらのサーバーの URL を
そのまま `<img>` で参照すると、サーバーを移したり止めたりしたときに過去の記事の画像が全部消える。
1枚目はアイキャッチ画像になる。

画像の登録に1枚でも失敗したら記事は作らない。画像の抜けた記事が公開されるより、
作られない方が気付けるため。

### URL はリンクになる

本文に URL を書くと、記事の中で `<a>` になる。**WordPress は本文中の裸の URL を既定では
リンクにしない**（`make_clickable` は本文の既定フィルタに入っていない）ため、こちらで変換している。

```
詳しくは https://example.com/news をご覧ください
→ 詳しくは <a href="https://example.com/news">https://example.com/news</a> をご覧ください
```

文末の句読点（`。` `.` `、` など）はリンクに含めない。変換は**エスケープした後**に掛けるので、
本文に HTML を書いてもタグとしては出ない。

## 写真なしの投稿（WordPress / X）

お知らせ・営業日の連絡など、写真の無い記事もそのまま投稿できる。

1. 「SNS投稿」で写真を1枚も選ばない
2. **「補足・記事にしたい内容」**に要点を書く（1000文字まで）。URL もここに書く
3. WordPress のカードで「**自動で書く**」を押すと、その要点だけをもとに下書きができる
4. 内容を確かめてから投稿する

> **要点に書いていないことは書かせない。** 日付・料金・時間・条件を勝手に補わないよう
> 指示してある。写真から書くときの「写真に写っていることだけ」と同じ考え方で、
> **材料の外へ出させない**のが要点。URL も一字一句そのまま残させる。
>
> ただし**下書きであることは変わらない**。必ず読んでから投稿すること。

写真ありのときは、これまでどおり写真を見て書く（「補足」は補助として効く）。
Instagram とスレッズは写真が必須なので、この使い方はできない。

### 設定できているかの確認

```bash
node --env-file-if-exists=.env scripts/check-env.js
```

`✓ WordPress: 店長（draft / 投稿モード: dry_run）` のように、接続できたログイン名が出る。

## 投稿先を増やすとき（開発者向け）

投稿先ごとの `if` を各所に足していくと、どこか1か所を直し忘れて「その投稿先だけ挙動が違う」が
起きる。増やすときは次の2つだけで済むようにしてある。

1. `src/sns/platforms.js` の表に1行足す（枚数・分割の有無・本文の上限）
2. `publishPost({ imageUrls, caption })` を持つクライアントを書き、`src/index.js` の
   `snsClients` に足す

`publishPost` は `{ status: 'published' | 'dry_run', mediaId }` を返す。
`postMode` を公開しておくと、画面のバッジに「実投稿 / dry_run」が出る。

配信そのもの（予約時刻の判定・二重投稿の防止・失敗時のスタッフ通知）は
`src/jobs/snsPublisher.js` が投稿先を問わず面倒を見るので、クライアント側では何もしなくてよい。
